Native signing uses an explicit approved disclosure copied into the issued snapshot. Blank disclosures retain the manual signing path. Signer contacts must be verified, MFA confirmed, current TOTP verified, typed name must match the issued person, and the one-use review must bind the exact immutable document hash and expire within ten minutes. A TOTP time step cannot sign two agreements. Signed PDFs use the same private encryption, bounded parser and real ClamAV path as manual evidence. Staff independently approve execution. This is an auditable application signing mechanism, not a third-party qualified certificate or legal enforceability claim.

Metrics use explicit cohorts. Renewal rate counts distinct approved renewal source leases divided by executed agreements ending in the selected window (default prior 90 days). Collections use net allocations after reversals over net invoices after credits, by due-date cohort as of now. Reconciliation lists verified/refunded/allocated/unused funds and exceptions for transaction creation cohorts. Operations/finance room filters group residents with a stay in selected inventory; they do not claim cost attribution to a specific historical room. No denominator produces “no observations,” not a fabricated rate.

Application monitoring records pseudonymous hashed subjects and bounded hourly alert aggregates; raw codes, keys, passwords, request bodies and email addresses are not stored in alerts. Global authentication signals require client-wide administration; property reviewers can see only permitted property signals. Host/network intrusion detection, alert routing, TLS/certificates, offsite recovery, independent security review, legal/client content, real provider delivery and staffed support/training remain explicit release/handover gates.

Accessibility failures discovered during this audit were fixed in CSS (table header/summary contrast and signed-agreement link target spacing). The production browser suite then passed all eight journeys and expanded automated WCAG checks without disabling rules. New screenshots use only actual synthetic browser fixtures with empty signing code fields, not real credentials or client records.

The signature-review audit also exposed a missing rejection path: execution now rejects a file whose review state is REJECTED, and staff can return the agreement for a new signature with a reason. The original signature hash/event stays retained, pending reviews are invalidated, and a new scanned version can be submitted and independently executed. A regression exercises the complete rejected-copy/return/replacement flow.
