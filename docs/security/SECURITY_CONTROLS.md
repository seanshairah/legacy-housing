## Release conditions

Production deployment requires a clean dedicated database or a fully verified shared-tenant configuration, least-privileged runtime roles, approved HTTPS origin, private networks/storage, managed secrets, current scanner signatures and external monitoring. Migration/backup roles must be separate from runtime credentials. The development Docker database and trust authentication are unsuitable for a public interface.

The application does not grant a Corelith operator automatic access to personal records. Any operational access requires a documented, time-bounded grant and audited work. Database superusers and host administrators remain privileged trust boundaries; application permissions cannot constrain a malicious infrastructure administrator.

Open gates and ownership are maintained in [REMEDIATION_REGISTER.md](../audit/REMEDIATION_REGISTER.md) and [MIPF_TECHNICAL_READINESS.md](../MIPF_TECHNICAL_READINESS.md).
