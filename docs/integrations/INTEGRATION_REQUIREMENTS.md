# Integration activation requirements

The configured production state is disabled or awaiting credentials until actual provider contracts pass. Test fixtures intercept provider transport only in guarded local test databases; they are never live-provider evidence. The adapter code is in `src/integrations`, gateway logic in `src/domain/paynow.ts`, delivery logic in `src/domain/worker.ts` and public discovery at `/api/v1/openapi`.

## Secret and tenant boundaries

Put secrets in secure deployment settings. Store per-organisation credentials encrypted when the organisation adapter supports them; the adapter must resolve credentials using the already authorized payment/property context. Never fall back to another organisation's merchant because a tenant credential is absent. A database configuration row alone does not establish that a provider adapter uses it safely.

Global environment credentials remain suitable only for the explicitly dedicated deployment they represent. Do not enable shared-client money processing until per-organisation initiation, callback credential resolution and worker isolation are executed successfully. Provider webhook routing must identify an intent without trusting a client-supplied tenant, then validate that intent with its merchant key.

Required outbound hosts for existing transports are `www.paynow.co.zw`, `api.resend.com` and `smspop.co.zw`. Add only approved destinations; maintain TLS/checksum verification and reject redirects/arbitrary provider URLs. Never paste secrets into issues, logs, commands or documentation.

## API and exchange contract

Session commands require exact-origin CSRF checks and share service rules with server forms. Delegated API keys are hashed, expire after 30 days, restrict reads to one property/capability and recheck the issuer's current grants. Collection reads return bounded pages. Exports need a deterministic continuation path or a durable background generation job at larger volumes; a silent `take` limit is a correctness failure.

Minor units are serialized as decimal strings. The receiving system must apply the confirmed currency exponent; no FX is performed. Refund commands record a confirmed external refund and append reversals; they do not initiate bank movement. Browser payment returns and uploaded evidence do not establish a successful gateway settlement.

WhatsApp, external write synchronization, OAuth delegation and outbound integration webhooks remain inactive until agreed contracts and acceptance tests exist. Documentation and a configurable adapter interface do not make these live integrations.
