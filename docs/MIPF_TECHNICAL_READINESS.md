## Release blockers and exact next actions

1. **Engineering:** finish an explicit request/job/worker/webhook data-plane context for every shared-runtime caller, route all tenant-owned persistence through restricted database access, separate migration/control-plane credentials, and rerun the complete suite with the actual non-owner runtime role. The organisation property API already demonstrates the restricted transaction path. Do not remove the shared-mode guard to bypass this work.
2. **Engineering and DPO/legal:** define and implement approved complete person-data correction/erasure execution, retained financial/lease identity requirements, backup/subprocessor disposal and legal-hold review. Existing document payload deletion is a working vertical feature, not complete account erasure. Approve actual schedules/bases before enabling retention execution.
3. **Client/providers:** approve factual inventory/rates/branding, privacy/lease/signature/cancellation/priority/SLA policies; configure approved merchant/senders and execute real sandbox/method/currency/delivery/outage acceptance. No credentials or funds were invented.
4. **Hosting/release owner:** provision approved-region private services, least-privileged runtime, managed keys/versioning/storage, TLS/trusted ingress, monitoring/alert responders, offsite backup/key escrow and fresh-host recovery; perform representative load and independent security/manual accessibility acceptance.
5. **Integration owners:** agree named external ERP/PMS/SIS/KYC/access-control contracts/mappings and implement only required writes. OAuth/outbound integration webhooks and third-party signature certificates are not represented as delivered.
6. **Commercial/service owners:** confirm support/training responsibilities and resolve the estimated operating-cost shortfall against the unchanged US$100 annual hosting quote; see [HOSTING_COST_MODEL.md](operations/HOSTING_COST_MODEL.md). Local code cannot establish staffed support or amend commercial terms.

No production deployment, live customer processing or real financial transaction was performed. The two original student-system references remain read-only. The release owner must review these blockers and recorded evidence before production approval.
