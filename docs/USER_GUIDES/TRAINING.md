# Practical training and operator acceptance

Use only synthetic accounts in the local `legacy_dev` database, with Paynow disabled and test files. Read the role guide first. Do not show local passwords or documents in a recording. A trainer and named client operator should record completion, questions and approved policy versions; these exercises are materials, not proof a live training session occurred.

| Role                   | Exercise                                                                                                                                                                 | Successful result                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| Resident               | Register, verify email/mobile through configured delivery, enroll an authenticator, browse dates/floor/category and review tenancy conditions                            | A single bed/date hold, versioned consent and clear next action; unavailable beds cannot be reserved                                   |
| Admissions/KYC         | Review a synthetic clean PDF, reject and request a new version, approve required evidence, approve application                                                           | Quarantine cannot be bypassed, history retained, deposit/signing stages remain distinct                                                |
| Finance                | Issue rent/utilities/penalty invoices; submit a bank proof or staff cash voucher; have a different reviewer verify; exercise a partial payment/overpayment/refund record | Exact outstanding/unused-credit/receipt values; proof is not settlement; reconciliation CSV matches source records                     |
| Resident/leasing       | Read an approved agreement online; sign electronically using exact name/disclosure/authenticator; download the signed copy; alternatively upload a scanned manual copy   | Exact source and signed-file hashes retained, separate staff execution review required; changed/expired/replayed signing requests fail |
| Property operations    | Check in an approved resident, create/respond/attach/resolve/reopen a ticket, inspect checkout and release turnover block                                                | Required arrival criteria enforced, responses and attachments visible only to authorized people, SLA escalation recorded               |
| Management             | Filter reports by property/room/period; inspect renewal cohort, complaint month buckets, rent arrears and collection denominator                                         | Explain each denominator and “no observations”; finance remains separately permissioned                                                |
| Administrator/security | Generate five synthetic failed sign-ins, investigate the alert, acknowledge/resolve with a reason, review audit, revoke a role/key/session                               | No credentials/email payloads in security alerts; cross-property review denied; revocation takes effect immediately                    |
| Operator               | Run encrypted backup and restore to a new disposable database; compare counts/hashes; simulate worker/provider outage and retry                                          | No production overwrite; immutable records reconcile; failure is visible; no invented delivery/payment success                         |

Before live training, configure approved terms/disclosures, real inventory, provider sandbox accounts, and a clean nonproduction training dataset. Before handover, assign named owners for access approval, payment reconciliation, privacy requests, incident response, key custody and offsite recovery. Agree support hours, response targets, escalation contacts and maintenance responsibility in a service agreement; software documentation cannot supply an ongoing staffed support service.
