## Data minimization and configuration

Email/SMS update notices identify a record change and direct the user to the authenticated portal; they do not attach identity/medical evidence. Identity challenge payloads are encrypted while queued and stored only as hashes in the verification table. API exports deliberately omit authentication secrets. A signed lease embeds the agreed resident/property/space/term facts necessary for its evidence; this remains personal data requiring restricted retention.

Organisation metadata can record branding, declared residency region, privacy/retention references and encrypted merchant configuration. A text region setting does not move data or constrain a cloud vendor. Actual data residency requires infrastructure selection, egress policy, subprocessor contracts and verification. Shared-client operation remains blocked until all application/worker/webhook paths use proven tenant isolation; a dedicated MIPF deployment remains the safe current option.

## Subprocessor approval record

For each activated provider record its legal entity, service purpose, data fields, processing/storage/support regions, subprocessors, contract/DPA version, security evidence, deletion/retention terms, incident contact, transfer basis and MIPF approval reference. Assign an owner and review date. The fixed network hostname is technical routing evidence, not proof of a legal entity or jurisdiction.

Resend, SMS Pop, Paynow, hosting/database/storage/backup providers, external signature/identity suppliers, monitoring vendors and receiving institutions each require an actual approved record before real processing. The repository currently contains their technical interfaces and activation requirements; it does not contain completed vendor due diligence or signed contracts.
