Interfaces are in `src/integrations/contracts.ts`; concrete local exchange and gateway adapters are in `src/integrations/index.ts`. The hub exposes actual scoped exports and a **local** test-connection operation. It does not call that test a live sandbox test. A selected ERP, SIS or PMS API requires a separate configured adapter and its contract tests; no invented Odoo or university endpoint is present.

## API

`GET /api/v1/openapi` publishes an OpenAPI 3.1 discovery contract. Versioned collection routes cover inventory, applications, leases, invoices, payments, tickets, analytics and integration status. `propertyId` is mandatory; collection pages contain up to 50 records. `from`/`to` filter creation dates on relevant resources. Minor units serialize as decimal strings. Read-only delegated keys expire after 30 days, are stored hashed, and still recheck the issuing user's current role/property grant. Revocation is immediate. Create/revoke in the integration workspace; raw token appears once and is never logged.

`GET /api/v1/exchange?propertyId=...&provider=ACCOUNTING_CSV` (or SIS_CSV/PMS_CSV) uses the adapter registry. Generic export is paginated; CSV formulas are escaped. `POST /api/v1/commands` uses the browser session and exact-origin CSRF validation, with the same command services as forms. Machine keys are read-only. Write exchange/import and outbound external webhook delivery are not claimed implemented; validate destination/provider requirements before enabling them.

For exports, chart-of-accounts/tax mapping is the accounting operator's explicit import mapping. Minor units must be divided by the configured currency exponent (currently two) in the receiving system; no silent FX. Invoice/customer/payment keys must remain stable. Importing a CSV into another system is an operator-reviewed act, not an automatic synchronization claim.

## Provider configuration

Set Paynow integration ID/key, verified merchant currency and `PAYNOW_MODE=live` only with approved HTTPS `APP_URL`. Set Resend key and verified `EMAIL_FROM`; set SMS Pop key and approved sender for mobile challenges. Required destinations: www.paynow.co.zw, api.resend.com, smspop.co.zw. Cloud configuration is additive; do not replace an unknown existing network list. Keys belong in secure deployment settings, not this repository or chat. Validate actual gateway response hashes, returned references and amount representation in the merchant sandbox before enabling real collections. Hosted checkout exposes only the payment methods the merchant actually supports. Refund commands record externally verified refunds and append allocation reversals; they do not initiate bank movement. Signed authoritative full-refund polling records an idempotent full reversal, including when a refund arrives before a paid callback. Ambiguous initiation prevents replacement intents until reconciliation. Hash normalization was checked against the official paynow 2.2.2 Node SDK published on npm; actual merchant sandbox validation is still unrun.

Production filesystem encryption keys must be backed up securely with their version metadata and rotated through an offline re-encryption process, preserving immutable plaintext hashes. Never replace a key in place and assume existing data remains decryptable. WhatsApp is not enabled: official Business Platform/provider approval and opt-in/template approval are prerequisites.
