## Failures investigated and corrected

The expanded tests first reproduced: HTTP redirects behind TLS; empty optional waitlist hash rejection; reminder starvation beyond 100; waitlist starvation after 50 and bed 100; export truncation after 500; missing raw-SQL serialization retry; internal ticket-note/attachment exposure; inherited notification-template names and unsafe log fields; upload size code rendered generically; and the new navigation link's insufficient target size. A final negative test also reproduced property-admin promotion into a new single-property organisation; the compatibility fallback is now limited to MIPF and new organisations require an explicit ADMIN organisation grant. New regression assertions remain enabled.

The first consolidated browser run had 20 passes and two failures (upload error display and navigation target size). A later run exposed a collapsed-ticket test interaction; while its correction was being made, Docker VFS build layers exhausted workspace disk and interrupted browser artifact/signing checks. This was an infrastructure failure, not recorded as a pass. Only obsolete target image/build cache and the owned temporary smoke container were removed; database/scanner containers and volumes were retained. The final browser result above supersedes interrupted runs. No test assertions were disabled to obtain a pass.

## Reproduction and practical limits

Use Node 24, PostgreSQL 16, Chromium and real ClamAV. Run `./scripts/setup-local.sh`, deploy migrations separately to isolated unit/browser databases, then the commands above. Full browser mode starts a production web process, a real worker and local HTTPS proxy; only fixed Paynow/Resend/SMS transport destinations are redirected into guarded test fixtures. It does not send real funds or real messages. CI now runs coverage, isolated HTTPS browser journeys and a fresh encrypted recovery drill.

This is a broad regression suite, not proof of perfection. Live Paynow merchant/method/currency acceptance, real sender delivery, host TLS/least privilege, fresh-host/offsite recovery, representative 100–1,000-resident capacity, independent penetration/manual accessibility review and legal/client acceptance remain unexecuted. Shared runtime is deliberately rejected by `TENANCY_MODE=shared` until all control-plane/data-plane boundaries are integrated. See the readiness report for internal as well as external blockers.
